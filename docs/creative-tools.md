# Creative boards and layered painting

Choose **New Board** in the workspace or open the creative board from the editor toolbar. Draw, Diagram and Elements share one editable board; Painting opens a focused layered surface. Boards retain pressure-sensitive ink, shapes, editable paths and text, bound connectors, imported media and artwork embeds. Paint offers bristle, dry brush, wash, smudge and eraser using the same pixel engine as the approved drawing lab. Each completed gesture joins project undo/redo. Use Save Board inside the board workspace, or close the workspace and Save; Live mode persists completed local edits after the creative workspace closes. In-flight Live responses wait until close before reconciling. Uploading tiles alone does not save a project revision.

## Document and agent contract

[Document schemas](../src/shared/schema.ts) read v1 and v2. Creating a board or painting upgrades the current document; ordinary legacy edits keep v1. The pure [upgrade](../src/shared/document-upgrade.ts) preserves IDs, page layout and project kind. Undo does not downgrade v2 or reuse a painting generation. A stored v2 project rejects v1 saves and merges, including requests with a current revision.

Use `dsa schema --operations`, MCP `studio://operations`, or browser `studio_capabilities` for the [shared operation contracts](../src/shared/operations.ts). Board operations include transforms, arrangement, grouping, paste and semantic diagrams; [painting layer operations](../src/shared/painting-layer-operations.ts) retain generation checks for layer/group changes. REST document PUT, MCP `update_document`/`patch_document`, CLI document operations and WebMCP use these same validators. For a real stroke or fill, use `POST /api/projects/{id}/paint`, MCP `paint_document`, or `dsa projects paint PROJECT_ID --file command.json`. Discover `paintingCommand` in `/api/schema`; the generated WebMCP API tool uses the same endpoint. Carry the observed document revision, painting generation, and a unique operation ID; retry the exact command under the same ID only after an uncertain response. The server renders owned pixels and commits through the document save service. A provider proposal is not itself a pixel renderer. The browser supplies real pressure when available and estimates mouse pressure from movement speed.

Paint source is an ordered layer manifest of immutable 512×512 RGBA8 PNG tiles, with checksums, dimensions, visibility, opacity, blend mode, masks and clipping settings. The [compositor](../src/shared/paint-composite.ts) supports normal, multiply, screen and overlay in sRGB; groups apply visibility and opacity to their member layers. The server verifies PNG dimensions/checksums and builds the persisted composite itself. It does not trust an uploaded preview. Brush pickup samples the frozen visible composite while deposits affect the selected layer. Layer controls include naming, ordering, duplication/deletion, visibility, locking, opacity, blend, alpha lock and clipping. Same-painting concurrent source/settings edits conflict as a whole; a composite-only server refresh is not a source edit. Independent board elements and separate paintings can merge.

Painting saves accept optional `operationId` in document PUT. Retry the same ID, exact document and expected revision after an uncertain response; a changed payload with that ID conflicts. Without an explicit ID, an exact retry derives the same identity from its payload and revision. The latest eight successful painting-save receipts per project are retained. Older retries receive a revision conflict; re-read and reconcile rather than guessing a revision. Brief approval remains separate.

## Assets and public output

The [asset lifecycle](../server/asset-lifecycle.ts) atomically reserves in-flight upload bytes against 2 GiB per project and 8 GiB per owner, including retained assets. Painting processing admits one job per owner and two per installation with a 60-second processing lease. A save is bounded to 64 megapixels of changed composite output and 512 megapixels of source tile/mask input before processing starts. Failed operations leave the last saved document intact. Uploaded immutable assets are retained until project deletion; automatic tile/history garbage collection is not enabled. Storage limits therefore include abandoned uploads and old undo assets.

Publication and shared exports use a [render projection](../src/shared/public-creative-projection.ts). It replaces painting sources with the verified visible composite and removes hidden board elements and their private assets. Public asset routes authorize only assets in that projection. JSON export remains the private editable document; it is not a portable asset archive. Clone copies owned bytes and remaps nested references. Duplicating an embed creates independent editable content while sharing immutable bytes safely.

Board/painting-dependent compositions cannot yet be packaged in reusable design-system libraries. Applying tokens and inserting legacy compositions preserve v2 roots. Use editable page embeds or project clone for creative content.

Unsaved Board edits are kept in account/project-scoped browser storage, with explicit restore/discard on reopening. A failed stroke or layer update retains a bounded local transaction. The [draft store](../src/app/painting-draft-store.ts) scopes durable browser recovery by account, project and painting. Retry reuses prepared work after successful uploads; it does not rerun smudge over changed pixels. A rejected merge never overwrites newer painting data. Download PNG backup preserves the visible local result, or explicitly discard it. Browser storage can be unavailable or cleared, so recovery feedback must be acted on before leaving the workspace.

## Human workflows

Board selection provides numeric transforms, flip, opacity, arrange/align, grouping and frames. Keyboard arrows nudge the selection; Shift increases the step. Copy/paste retains internal bindings through the [selection bundle](../src/shared/board-selection.ts). The [diagram panel](../src/app/diagram-panel.tsx) provides flowchart, architecture, user-flow and mind-map examples, editable roles/labels, bound connections, routing and layered/tree/radial layout. Locked or pinned nodes and manual bends constrain layout instead of being silently replaced. New templates are placed below existing artwork. If overlapping nodes leave no obstacle-free connection, every viewer and export keeps a dashed connection with a route warning; move the obstruction or add bends to repair it.

[Elements](../src/app/creative-elements-panel.tsx) searches original MIT artwork, semantic emoji variants and project-owned images/GIFs. Bundled artwork stores supported PNG pixels with a stable, original vector-recipe identity for deterministic recoloring; imported SVG is checked against a restricted primitive/attribute set, then flattened to PNG with an explicit notice. Scripts, external resources and unsupported SVG content are rejected. Flattened images do not retain editable vector paths. Paintings can be inserted as editable references.

GIFs begin paused. Playback, looping, timeline start and poster selection use the shared [millisecond clock](../src/shared/creative-elements-gif-playback.ts). Original GIF bytes stay owned assets; posters and exact export frames are derived pixels. Live GIFs share board order, transforms and frame clipping with vectors. Reduced-motion preference selects the poster. Static output uses the saved poster; timed browser exports sample the chosen frame. Decoder limits are admission bounds, not measured device performance; inspect [GIF preflight](../src/shared/gif-bounds.ts) before increasing them.

Painting adds rectangle/lasso selections, feathering, tolerant contiguous or whole-layer fill, resize, groups and masks to the [workspace](../src/app/painting-workspace.tsx). Settings, pixels and masks participate in painting generation checks. Locked layers/groups must be deliberately unlocked before edits that alter their contents.

## Acceptance limits

The [active plan](../plans/260910-1852-board-paint-diagram/plan.md) tracks observed browser, runtime and artifact evidence separately from implementation. Local browser or CPU checks do not establish physical iPad/Pencil latency, palm handling, peak process memory, or a live deployment. Physical-device acceptance remains unmeasured. Inspect the actual exported artifact before claiming fidelity, and keep generated runtime/source inventories synchronized through the owning build scripts.

Select a Board embed in the page editor to edit **Board view** crop coordinates and dimensions in the inspector. **Create linked view** shares the editable source board while keeping its own crop; **Duplicate** creates independent board content. Panning or zooming the creative workspace does not change the page embed crop.

MCP authorization identity clarification: the [MCP authorization contract](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization) binds authorization to a protected resource, without requiring a stable remote account identifier. Generic MCP `remoteIdentity` may therefore be null after verified authorization. Native adapters still require their provider account IDs. Every new human authorization must invalidate previous grants/approvals even when no account ID is available; refresh stays bound to the same issuer/resource and credential lease. This corrects a foundation assumption, not a claim of user identity verification.
